### coder:pages-artifact-cleanup -- Stop Pages deploy artifacts from filling the free 0.5 GB Actions storage (the cause of the 2026-11-06 account lock) -- Trisha-directed 2026-11-06

- **Dependency:** the GitHub account lock must be lifted first (CI cannot run while locked; check with any `workflow_dispatch` run). Not blocking the build itself.
- **Handoff:** none needed; this block is the spec. Copy it to `docs/overnight-coder-handoffs/archive/pages-artifact-cleanup.md` as the PR's first commit.
- **Readiness:** READY, with the workflow-push caveat below. Ends at a DRAFT PR. Do not flip any flag.
- **What happened (verified 2026-11-06):**
    - On 11/5 between 18:17 and 21:17 UTC, `pages.yml` ran 8 times (6 `push` runs from a burst of commits in ~20 min, plus 2 `workflow_run` redeploys). Each `actions/upload-pages-artifact@v5` step stored a `github-pages` artifact of **67 MB** (the whole `site/`, including the full-text search bundle). Default retention is 1 day, so all 8 (**539 MB**) were stored at once, over the free plan's **0.5 GB** Actions artifact storage (pooled with Packages).
    - The account has no payment method (free plan; all compute is free because the repo is public). GitHub's docs: "If your account does not have a valid payment method on file, usage is blocked once you use up your quota." GitHub emailed "we cannot bill your account" at 09:26 UTC on 11/6 and every Actions job since ~11:10 UTC failed at startup with "account is locked due to a billing issue" (11 runs; daily nSITE watcher and gfl-air never ran).
    - Trisha OK'd deleting the 8 artifacts at ~16:48 UTC (storage now 0.28 MB). Caches (3.3 GB) are a separate 10 GB-per-repo allowance and are fine. `bandit-report` artifacts are tiny (~0.1 MB total) and need no change.
- **Do:**
    (a) **Delete the Pages artifact after a successful deploy.** In `.github/workflows/pages.yml`, add a final step after `actions/deploy-pages` (same `if:` guard as the deploy, plus `success()`) that deletes the `github-pages` artifact(s) uploaded by THIS run (`GET /repos/{repo}/actions/runs/{run_id}/artifacts`, then `DELETE /repos/{repo}/actions/artifacts/{id}` for name `github-pages`). Add `actions: write` to the workflow `permissions` (keep `contents: read`, `pages: write`, `id-token: write`). Use `gh api` with `GH_TOKEN: ${{ github.token }}`. Delete only AFTER the deploy step succeeded: `deploy-pages` needs the artifact while it runs.
    (b) **Safety net for older leftovers:** in the same step, also delete any `github-pages` artifact from an EARLIER run that is still unexpired (a prior cleanup that failed, or a run that failed after upload). Never touch other artifact names.
    (c) **Fewer redundant deploys (smaller, optional):** consider a short debounce for `push` bursts (e.g. `concurrency: group: pages` already serializes; leave `cancel-in-progress: false` per GitHub's Pages guidance, since cancelling a running deploy can leave Pages half-deployed). Do NOT add a sleep-based debounce. If there is a clean way to skip a `workflow_run` redeploy when `site/` is unchanged, describe it in the PR, but (a)+(b) are the fix; (c) is not required.
    (d) **Early warning:** add a check (a new small script under `scripts/`, called from an existing daily job such as the liveness / owner-notice path, or its own step in `daily.yml`) that sums the repo's unexpired artifact bytes via the API and sends the existing owner-only alert (ADR 070, `owner_notices.py`) when it exceeds **350 MB** (70% of the 0.5 GB allowance). Counts and bytes only in logs (public-log rule: no artifact URLs or signed links).
    (e) Tests: a unit test for the threshold logic in (d) with mocked API responses; a test that parses `pages.yml` and asserts the cleanup step exists, runs after the deploy step, and only targets the `github-pages` name.
    (f) Docs: update `docs/architecture.md` (pages entry) with one paragraph: why the cleanup exists, the 11/6 lock, the 0.5 GB allowance.
